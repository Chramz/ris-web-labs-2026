## Таблица запросов

| Метод и путь | Тело | Успех | Возможная ошибка |
|---|---|---|---|
| `GET /api/bookings` | — | `200`, массив броней или `[]` | — |
| `GET /api/bookings/{id}` | — | `200`, объект брони | `404` |
| `POST /api/bookings` | `title`, `roomId`, `date`, `time`, `description` | `201`, в ответе `id`, `number`, `status: New` | `400` |
| `PATCH /api/bookings/{id}/assignee` | `assigneeUserId` | `200`, обновлённая бронь | `404` |
| `PATCH /api/bookings/{id}/status` | `status` | `200`, обновлённая бронь | `404`, `409` |

Коды ответов: `200` — ок, `201` — создано, `400` — некорректные данные, `404` — такой записи нет, `409` — так нельзя по правилам (например, смена статуса чужой брони).

Правила именования:

- удаления (`DELETE`) в API нет: отмена брони — это статус `Cancelled`, строка остаётся;
- пути вида `/api/bookings/create` не используются: действие несёт метод `POST`, а не слово в адресе;
- назначение исполнителя и смена статуса — два разных PATCH, это разные действия с разными правилами;
- пустой список — это `200` и `[]`, а не `404`.

## 1. Создание брони

`POST /api/bookings`

Тело запроса:

```json
{
  "title": "Волейбол, группа ТРИС-2-23",
  "roomId": 1,
  "date": "2026-09-25",
  "time": "14:00",
  "description": "Пара физкультуры, нужны мяч и сетка"
}
```

Клиент **не** присылает `id`, `number`, `status` и `assigneeUserId` — их определяет сервер.

Успех `201 Created`:

```json
{
  "id": 17,
  "number": "Б-17",
  "status": "New"
}
```

Ошибка `400 Bad Request` (заголовок короче 5 символов):

```json
{
  "error": "Поле title должно быть от 5 до 80 символов"
}
```

Запись при ошибке не создаётся (ФТ-3, НФТ-4).

## 2. Список броней

`GET /api/bookings`

Успех `200 OK`:

```json
[
  {
    "id": 17,
    "number": "Б-17",
    "title": "Волейбол, группа ТРИС-2-23",
    "status": "New",
    "roomId": 1,
    "date": "2026-09-25",
    "time": "14:00",
    "assigneeUserId": null
  }
]
```

Если броней нет — тот же `200 OK` с телом `[]`.

## 3. Одна бронь

`GET /api/bookings/17`

Успех `200 OK` — объект брони со всеми полями. Ошибка `404 Not Found` — брони с таким `id` нет.

## 4. Назначение исполнителя

`PATCH /api/bookings/17/assignee`

Тело запроса:

```json
{
  "assigneeUserId": 3
}
```

Успех `200 OK` — у брони появился исполнитель, статус остаётся `New` (ФТ-6). Ошибки: `404` — брони нет.

## 5. Смена статуса

`PATCH /api/bookings/17/status`

Тело запроса:

```json
{
  "status": "InProgress"
}
```

Допустимые значения: `New`, `InProgress`, `Closed`, `Cancelled`.

Успех `200 OK` — статус обновлён. Ошибки: `404` — брони нет; `409 Conflict` — попытка сменить статус брони, которая не назначена этому администратору (ФТ-10).
