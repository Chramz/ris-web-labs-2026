## Схема из трёх узлов

```text
Vue 3 + Vite              ASP.NET Core              PostgreSQL
localhost:5173  ───────►  localhost:5000  ───────►  обычно :5432
                  HTTP                    запросы к БД
        (пример: POST /api/bookings)
```

> архитектура web-ИС семестра

Это и есть архитектура web-ИС семестра: три узла, две связи, один источник правды о бронях. Не микросервисы и не «сайт на одном файле».

## Роли узлов

| Узел | Порт | Что делает |
|------|------|------------|
| Vue 3 + Vite (клиент) | 5173 | Рисует экраны (вход, список броней, создание брони), отправляет HTTP-запросы |
| ASP.NET Core (сервер) | 5000 | Проверяет правила (обязательные поля, роли, переходы статусов), отвечает клиенту |
| PostgreSQL (база) | обычно 5432 | Хранит брони, залы и пользователей |

## Почему браузер не пишет в PostgreSQL напрямую

Прямой стрелки от браузера к базе на схеме нет — и это осознанное решение:

1. **Правила живут на сервере.** Проверка обязательных полей (ФТ-3), разграничение прав ролей (НФТ-2, ФТ-10) и допустимые переходы статусов выполняются в ASP.NET Core. Если бы браузер писал в базу напрямую, клиент мог бы обойти любую проверку.
2. **Один источник правды.** Если два пользователя открыли список броней, они видят одно и то же, потому что данные хранятся на сервере, а не в каждом браузере.
3. **Безопасность.** База не должна быть доступна извне; доступ к ней имеет только серверное приложение.

## Пример запроса целиком

Метод, путь, тело и код ответа:

```http
POST /api/bookings HTTP/1.1
Host: localhost:5000
Content-Type: application/json

{
  "title": "Волейбол, группа ТРИС-2-23",
  "roomId": 1,
  "date": "2026-09-25",
  "time": "14:00",
  "description": "Пара физкультуры, нужны мяч и сетка"
}
```

Ответ успеха:

```http
HTTP/1.1 201 Created

{
  "id": 17,
  "number": "Б-17",
  "status": "New"
}
```

Поля `id`, `number`, `status` и исполнитель клиент не присылает — их определяет сервер.
